📌 PROJECT OVERVIEW (30 seconds):
================================================================================
ChillAdda = Full-stack music streaming web app
- Stream millions of songs FREE
- Built with: Next.js 14 + MongoDB + Redux + JioSaavn API
- Features: Auth, Playlists, Favorites, Download, Lyrics, PWA
- Deployed: Vercel + MongoDB Atlas


🔑 KEY TALKING POINTS:
================================================================================

1. WHY JIOSAAVN API?
   ✅ 100% FREE (no API key, no rate limits)
   ✅ Direct streaming URLs (unlike Spotify)
   ✅ Huge music library (millions of songs)
   ✅ Simple REST API (no complex OAuth)
   ✅ Deployed on Vercel (free tier)

2. HOW IS IT FREE?
   → Open-source wrapper from GitHub (sumitkolhe/jiosaavn-api)
   → Deployed on Vercel's free tier
   → 100GB bandwidth/month
   → Accesses publicly available data
   → Educational/portfolio project

3. TECH STACK:
   Frontend: Next.js 14 (App Router) + React 18 + Tailwind CSS
   Backend: Next.js API Routes + MongoDB + Mongoose
   Auth: NextAuth.js + JWT + Bcrypt
   State: Redux Toolkit + Redux Persist
   External: JioSaavn API + Lyrics API
   PWA: @ducanh2912/next-pwa
   Deploy: Vercel

4. WHY NEXT.JS?
   → Built-in API routes (no separate backend)
   → Server-side rendering (better SEO)
   → Automatic code splitting (performance)
   → Image optimization (next/image)
   → File-based routing (easier navigation)

5. AUTHENTICATION:
   → Email/Password: Bcrypt hashing + JWT
   → Google OAuth: NextAuth.js
   → Tokens in HTTP-only cookies (XSS protection)
   → 30-day expiry
   → Password reset via email (Nodemailer)

6. DATABASE SCHEMA:
   User → {userName, email, password, imageUrl, userData}
   UserData → {favourites[], playlists[], songHistory[], language[]}
   Playlist → {name, songs[], user}

7. SECURITY:
   ✅ Bcrypt password hashing (10 salt rounds)
   ✅ JWT in HTTP-only cookies
   ✅ Environment variables for secrets
   ✅ Input validation (frontend + backend)
   ✅ API route protection (middleware)
   ✅ HTTPS (automatic on Vercel)

8. PERFORMANCE:
   ✅ 4-hour API caching (Next.js revalidate)
   ✅ Redux Persist (avoid re-fetching)
   ✅ Code splitting (automatic)
   ✅ Image optimization (next/image)
   ✅ Lazy loading
   ✅ Debounced search

🎯 BIGGEST CHALLENGE:
================================================================================
CORS issues with lyrics API

SOLUTION:
1. Used AllOrigins proxy (bypasses CORS)
2. Fallback mechanism (Musixmatch → YouTube)
3. Validation (check if lyrics are valid)

OTHER CHALLENGES:
- JWT security → Switched to HTTP-only cookies
- State persistence → Redux Persist
- Expired URLs → Re-fetch on error


🚀 HOW TO SCALE TO 1M USERS:
================================================================================
1. Database: MongoDB replica set + sharding
2. Caching: Redis for user data, API responses
3. CDN: CloudFront/Cloudflare for assets
4. Load Balancer: Distribute traffic
5. Microservices: Separate auth, player, playlist
6. Queue System: Background jobs (email, analytics)
7. Search: Elasticsearch/Algolia
8. Monitoring: New Relic, Sentry
9. Infrastructure: Kubernetes cluster
10. Cost: ~$2500-5000/month


📊 COMPLETE FLOW:
================================================================================

USER SIGNUP:
User input → Validate → Hash password (bcrypt) → Create User + UserData docs
→ Generate JWT → Set HTTP-only cookie → Redirect home

SONG PLAY:
Click song → Redux action → Fetch song data from JioSaavn API
→ Update Redux state → MusicPlayer renders → <audio> plays URL

CREATE PLAYLIST:
Click "Create" → Enter name → POST /api/userPlaylists → Verify JWT
→ Create Playlist doc → Link to UserData → Return success → Update UI

ADD TO FAVORITES:
Click heart → POST /api/favourite → Verify JWT → Toggle in UserData.favourites[]
→ Update UI → Show toast

SEARCH:
Type query → Debounce → GET /api/search → JioSaavn API → Return results
→ Display songs/albums/artists/playlists

DOWNLOAD:
Click download → Get downloadUrl → Browser downloads .mp3 → Show progress
