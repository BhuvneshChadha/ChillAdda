PROJECT OVERVIEW:
================================================================================
ChillAdda is a full-stack music streaming web application built with Next.js 14,
featuring user authentication, custom playlists, favorites, and song playback 
with lyrics. It's a Progressive Web App (PWA) that provides a Spotify-like 
experience.

GitHub Repository: https://github.com/BhuvneshChadha/ChillAdda


TECHNOLOGY STACK:
================================================================================

FRONTEND:
---------
- Next.js 14.2.1 (React Framework with App Router)
- React 18.2.0
- Redux Toolkit (@reduxjs/toolkit) - State Management
- Redux Persist - Persist Redux state across sessions
- Tailwind CSS - Styling
- React Icons - Icon library
- React Hot Toast - Notifications
- Swiper - Carousel/Slider
- React Swipeable - Touch gestures
- React Top Loading Bar - Loading indicator
- React Use Downloader - Song download functionality

BACKEND (Next.js API Routes):
-----------------------------
- Next.js API Routes (Server-side endpoints)
- MongoDB (via Mongoose) - Database
- NextAuth.js - Authentication
- Bcrypt.js - Password hashing
- JWT (jsonwebtoken) - Token-based authentication
- Nodemailer - Email functionality (password reset)

EXTERNAL APIs:
-------------
- JioSaavn API - Music data and streaming
- Lyrics API (lewdhutao) - Lyrics fetching
- AllOrigins Proxy - CORS bypass for lyrics

PWA FEATURES:
-------------
- @ducanh2912/next-pwa - Progressive Web App support
- Installable on mobile and desktop
- Offline capabilities

COMPLETE APPLICATION FLOW:
================================================================================

1. USER AUTHENTICATION FLOW:
   -------------------------
   
   SIGNUP:
   -------
   User fills signup form → Frontend sends POST /api/signup
   → Backend validates data
   → Password hashed with bcrypt
   → User document created in MongoDB (User model)
   → UserData document created (for favourites, playlists)
   → JWT token generated
   → Token stored in HTTP-only cookie
   → User redirected to home
   
   LOGIN:
   ------
   User enters credentials → POST /api/login
   → Backend finds user by email
   → Bcrypt compares passwords
   → JWT token generated (30-day expiry)
   → Token stored in HTTP-only cookie
   → User logged in
   
   GOOGLE LOGIN (NextAuth):
   ------------------------
   User clicks "Sign in with Google" → NextAuth handles OAuth flow
   → Google authentication
   → User created/updated in DB
   → Session established
   → Redirected to home
   
   PASSWORD RESET:
   --------------
   User requests reset → POST /api/forgotPassword with email
   → Reset token generated (crypto)
   → Token stored in user document with expiry
   → Email sent via Nodemailer with reset link
   → User clicks link → PUT /api/forgotPassword with new password
   → Password updated and hashed
   → Reset token cleared

2. MUSIC PLAYBACK FLOW:
   --------------------
   
   HOME PAGE:
   ---------
   Component loads → homePageData() called
   → Fetches from JioSaavn API: /modules?language=hindi
   → Returns: {
       trending: [...],
       charts: [...],
       albums: [...],
       playlists: [...]
     }
   → Data displayed in swiper carousels
   → 4-hour cache (revalidate: 14400 seconds)
   
   SONG SELECTION:
   --------------
   User clicks song → Redux action dispatched
   → Song data fetched: getSongData(songId)
   → Calls: /api/songs/{id}
   → Returns: {
       name, artists, image, downloadUrl (streaming URL)
     }
   → Redux playerSlice updates:
       - activeSong
       - currentSongs
       - currentIndex
       - isActive: true
       - isPlaying: true
   → MusicPlayer component renders
   → HTML5 <audio> element plays downloadUrl
   
   MUSIC PLAYER FEATURES:
   ---------------------
   - Play/Pause controls
   - Seekbar (progress tracking)
   - Volume control
   - Next/Previous song
   - Shuffle mode
   - Repeat mode (one, all, off)
   - Fullscreen mode
   - Download button (downloads .mp3)
   - Add to favorites
   - Add to playlist
   - Lyrics display
   
   LYRICS FETCHING:
   ---------------
   User opens lyrics → getlyricsData(songName) called
   → First tries Musixmatch API via AllOrigins proxy
   → If not found, tries YouTube lyrics API
   → AllOrigins bypasses CORS restrictions
   → Lyrics displayed in scrollable view

3. SEARCH FLOW:
   ------------
   User types in searchbar → Debounced input
   → getSearchedData(query) called
   → Calls: /api/search?query={query}
   → Returns: {
       songs: [...],
       albums: [...],
       artists: [...],
       playlists: [...]
     }
   → Results displayed in categories
   → User can click any result

4. PLAYLIST MANAGEMENT FLOW:
   --------------------------
   
   CREATE PLAYLIST:
   ---------------
   User clicks "Create Playlist" → Modal opens
   → User enters name → POST /api/userPlaylists
   → Backend:
       - Verifies JWT token
       - Creates Playlist document
       - Links to user's UserData
   → Playlist appears in sidebar
   
   ADD SONG TO PLAYLIST:
   --------------------
   User clicks "Add to Playlist" on song → Modal shows playlists
   → User selects playlist → POST /api/userPlaylists/songs
   → Backend:
       - Finds playlist by ID
       - Pushes song object to playlist.songs array
       - Saves playlist
   → Success toast shown
   
   DELETE SONG FROM PLAYLIST:
   -------------------------
   User clicks remove icon → DELETE /api/userPlaylists/songs
   → Backend filters out song from playlist.songs array
   → Playlist updated
   
   DELETE PLAYLIST:
   ---------------
   User clicks delete → DELETE /api/userPlaylists
   → Backend:
       - Removes playlist document
       - Removes reference from UserData.playlists
   → Playlist removed from UI

5. FAVORITES FLOW:
   ---------------
   User clicks heart icon → addFavourite(songId) called
   → POST /api/favourite with songId
   → Backend:
       - Finds user from JWT token
       - Checks if song already in favourites
       - If yes: removes it (toggle off)
       - If no: adds it (toggle on)
       - Updates UserData.favourites array
   → Icon color changes (red = favorited)
   → User can view all favorites in /favourite page

6. ARTIST/ALBUM PAGES:
   -------------------
   User clicks artist → Redirected to /artist/[id]
   → getArtistData(id) called
   → Returns artist info, top songs, albums
   → getArtistSongs(id, page) for pagination
   → User can play songs, view albums
   
   User clicks album → /album/[id]
   → getAlbumData(id) called
   → Returns album details and all songs
   → User can play entire album

7. RECOMMENDATION FLOW:
   --------------------
   Song is playing → getRecommendedSongs(artistId, songId)
   → Calls: /api/songs/{songId}/suggestions
   → Returns similar/related songs
   → Displayed below current song
   → Auto-play next recommended song (if enabled)

CHALLENGES FACED & SOLUTIONS:
================================================================================

1. CORS ISSUES WITH LYRICS API:
   Problem: Browser blocked cross-origin requests
   Solution: Used AllOrigins proxy to bypass CORS restrictions

2. JWT TOKEN SECURITY:
   Problem: XSS attacks could steal tokens from localStorage
   Solution: Stored JWT in HTTP-only cookies (inaccessible to JavaScript)

3. MUSIC STREAMING URLS:
   Problem: Some APIs don't provide direct streaming URLs
   Solution: JioSaavn API provides CDN URLs that work directly in <audio>

4. STATE PERSISTENCE:
   Problem: Player state lost on page refresh
   Solution: Redux Persist to save state to localStorage

5. LYRICS ACCURACY:
   Problem: Single API doesn't have all lyrics
   Solution: Fallback mechanism - try Musixmatch, then YouTube

6. LARGE MUSIC LIBRARY:
   Problem: Too many songs to load at once
   Solution: Pagination and lazy loading with Next.js caching

SAMPLE INTERVIEW ANSWERS:
================================================================================

Q: "Walk me through your project."
A: "ChillAdda is a full-stack music streaming application I built using 
   Next.js 14, MongoDB, and Redux. It allows users to stream millions of 
   songs for free, create playlists, manage favorites, and download songs. 
   I integrated the JioSaavn API for music data, implemented JWT 
   authentication, and deployed it as a Progressive Web App on Vercel."

Q: "Why did you choose Next.js over React?"
A: "I chose Next.js for its server-side rendering capabilities, built-in 
   API routes which eliminated the need for a separate backend server, 
   automatic code splitting for better performance, and excellent SEO 
   support. The App Router in Next.js 14 also provides better developer 
   experience with server components."

Q: "How did you handle authentication?"
A: "I implemented a dual authentication system - email/password using 
   bcrypt for hashing and JWT for tokens, plus Google OAuth via NextAuth.js. 
   Tokens are stored in HTTP-only cookies for XSS protection. I also added 
   password reset functionality with email verification using Nodemailer."

Q: "What was the most challenging part?"
A: "The most challenging part was handling CORS issues when fetching lyrics 
   from third-party APIs. I solved this by using AllOrigins as a proxy 
   server and implementing a fallback mechanism to try multiple lyrics 
   sources. I also had to ensure the music player state persisted across 
   page navigations, which I achieved with Redux Persist."

Q: "How do you ensure the application is secure?"
A: "I implemented multiple security measures: bcrypt password hashing, 
   JWT tokens in HTTP-only cookies, environment variables for sensitive 
   data, input validation on all API routes, and Next.js's built-in CSRF 
   protection. I also follow the principle of least privilege for database 
   access."
